拆分后的 contributions.json：settings 与 pages 彻底分离

插件设置 = 纯声明（settings），由宿主 VueFluentWidgets 渲染（开关 / 下拉 / 复选框 / 滑条 / 贡献选择器）； pages 只注册 iframe 富页面，不再承载 native 设置。 完整示例：examples/contributions.example.json。

settings顶层对象：sections[].fields[]。宿主生成「插件设置」页；普通字段写入 storageKey，贡献选择器走宿主注册表。
pages顶层数组：仅 entry iframe；禁止 native。location: dock|plugins 决定侧栏一级入口或插件区链接。
其余键commands / componentStylePacks / … 仍为贡献树，运行时并入 manifest.contributes。
字段类型toggle→FluentToggle · checkbox→FluentCheckBox · select→FluentSelect · slider→FluentSlider · 贡献选择器沿用现有 host control。
iframe 读设置与宿主设置共用 settings.storageKey；bootstrap 注入 CyrenePlugin.settingsKey（可选 settings.read/write）。需 storage:read / storage:write。宿主保存后 iframe 收到 plugin:storage-changed。
兼容旧包 pages[].native 继续可读；新模板/文档只产 settings。
旧模型把设置挂在 pages[].native，与 iframe 内容页共用 pages 数组，插件管理里一律标成「插件设置」。 拆开后：设置页永远是宿主 UI，内容页永远是 iframe。
